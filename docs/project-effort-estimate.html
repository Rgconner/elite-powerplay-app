⚠️ Risk Factors

Formula validation: The decay rates (2.6%→15.6% Stronghold, 0.1%→10.9% Fortified, 0.1%→5.3% Exploited) are estimates from game observations. A senior should verify against live data — could add 0.5–1 day if formulas need tuning.
Cycle caching edge cases: The "compute once per cycle, reuse" pattern requires careful handling of the Thursday 07:00 UTC boundary. Off-by-one errors are likely — budget 0.5 day for testing.
Frontend regression: Updating Net calculations across 4 views touches shared display logic. A visual regression pass is needed — budget 0.5 day.
Spansh API stability: The entire data pipeline depends on Spansh's search API. Rate limits, schema changes, or downtime could delay Phase 2 by 1–2 days.
Game mechanic knowledge: Team members need to understand PP2.0 mechanics (merit thresholds, state transitions, decay formulas). Domain research is budgeted into Phase 1–2 but could expand if the game updates during development.
